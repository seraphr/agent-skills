## 前提

このスキルは、`/goal`機能とともに利用することを前提としています。
以下の条件を一つでも満たす場合は、実行を停止し、ユーザに実行条件を満たしていないことを伝えてください。

- 現在のスレッド・セッションに目標が設定されていない
- 目標としてGitHubのIssueが指定されていない

## 目標の完了条件

以下の条件をすべて満たしたときに、目標を完了したと判断してください。

- 指定されたGitHub Issueの本文及びコメントに書かれた要件・ユースケース・設計・決定事項などを全て満たしていること
    - 課題の内容を取得するには`<skill root>/scripts/show_issue.sh`コマンドが利用できます。
- コードレビューと修正を繰り返し、重要な指摘が無い状態になっていること
    - 実装が終わったら、`### コードレビューと修正の手順`に従って、コードレビューと修正を行ってください。
    - 上記の手順で、コードの修正が発生しなかった場合、`重要な指摘が無い状態`と判断します
    - 修正が発生した場合、はじめに戻って、再度コードレビューと修正を繰り返してください
- `.agent/temp/impl_${課題番号}`にレビュー情報が残っていること

ただし、`### コードレビューと修正の手順`のレビュー回数が5回を超えても修正が終わらない場合、目標の完了条件を満たすことが困難であると判断し、ユーザに報告した上で、処理を停止してください。


### コードレビューと修正の手順

1. **新規のサブエージェント（context fork無し）を起動し**、`diff-review`スキルを用いてコードレビューを行わせ、結果を受け取る
    - プロンプト: "$diff-review スキルを用いて、現在のdiffをレビューしてください。 実装中の課題は ${課題のURL} です。"
        - 新規のサブエージェントを使っているのは、過去の情報に囚われず、新しい視点でレビューを行うためです。
        - そのため、プロンプトに、過去のレビュー結果や修正内容を含めることは禁止します。
        - `修正後の再レビューです`のような、過去にレビューや修正を行ったという事実を伝えることも禁止します。
    - コードレビューを総括するエージェントタイプが利用可能であれば、そのエージェントタイプを指定して起動してください。
    - コードレビューが終わるまで、待機し他の行動はしない
2. 受け取ったコードレビュー結果を`.agent/temp/impl_${課題番号}/review_result-${レビュー回数}.md`に保存する
    - レビュー結果は要約せず、サブエージェントから受け取った内容をそのまま保存してください
3. レビュー結果を検証し、修正する指摘と修正しない指摘に分類する
    - 以下のような指摘は、修正しない指摘として分類してください
        - 正しくない指摘
        - 過去のレビューによって修正した内容と矛盾する指摘
        - 今回の編集範囲と関係のない指摘
        - `[P7]`および、それより数値の大きい重要度タグが付与された指摘
        - `[FYI]`タグが付与された指摘
    - 修正しない指摘は、`.agent/temp/impl_${課題番号}/not-fixed.md`に転記してください（ファイルが存在しなければ作成し、存在して入れば追記）
        - 転記の際に、修正しなかった理由を明示してください。
    - 修正する指摘は、`.agent/temp/impl_${課題番号}/fixed-${レビュー回数}.md`に転記してください（ファイルが存在しなければ作成し、存在して入れば追記）
        - 転記の際に、`修正内容`という項を作り、`<未修正>`と記載してください。
4. `.agent/temp/impl_${課題番号}/fixed-${レビュー回数}.md`に記載された指摘をすべて修正してください
    - 修正が終わったら、`.agent/temp/impl_${課題番号}/fixed-${レビュー回数}.md`の`<未修正>`を、実際に行った修正内容に書き換えてください


## 実装用サブエージェントの利用

実際のコード修正を行う場合、個別具体的な実装に関しては、実装用のサブエージェントを起動して作業させることができます。
もし、実装用のサブエージェントを利用する場合は、以下の点に注意してください。

- 実装用のサブエージェントには、設計方針、要件、公開API、依存関係、互換性、セキュリティ、性能などのトレードオフの判断が必要なタスクを実装させることは避けてください
    - そのような判断が必要な場合は、親エージェントが判断し、実装用のサブエージェントには、判断済みの方針に従って実装させてください
- 実装用のサブエージェントには、個別具体的な実装の指示を可能な範囲で与えてください
    - Objective: このタスクで達成する目的
    - Scope: 今回の作業に含まれる範囲
    - Files/components: 主な変更対象。変更禁止とは限らないが、範囲外の大きな変更が必要ならエスカレーションする
    - Required behavior: 実装後に必ず満たす外部から観測可能な動作
    - Non-goals: 今回は実装しない事項
    - Constraints: 実装時に守る制約
    - Acceptance criteria: タスクを完了と判断するための検証可能な条件
    - Validation commands: 完了前に実行する検証コマンド
    - Decisions already made: 親エージェントが決定済みであり、再検討しない事項
    - Escalate if: 作業を止めて親エージェントに判断を求める条件
- 実装用のサブエージェントによる編集が完了した後は、その内容が指示通りになっているか、指示に従った修正が行われているかを必ず確認し、必要に応じて修正してください
    - この修正をさらにサブエージェントに依頼しても構いませんが、指示通りに修正されているかの確認は必ず行ってください
- サブエージェントの起動時に会話コンテキストをどの程度引き継ぐかは、親エージェントの判断で決定してください
    - 判断に迷う場合は、会話コンテキストを引き継がずに新規のサブエージェントを起動することを推奨します
- 実装用のサブエージェントを利用する際に、既存の起動済みエージェントを利用するか新規に起動するかは、親エージェントの判断で決定してください
    - 同じファイルやコンポーネントを編集する場合など、既存の知識を再利用するのが効率的なときは、既存の起動済みエージェントを利用することを推奨します

## Available scripts

スキル配下には、以下のスクリプトが用意されています。

### `<skill root>/scripts/show_issue.sh`

指定された課題の内容を表示するコマンドです。
課題の本文、コメントを全て取得して標準出力に出力します。

実行例:

```bash
<skill root>/scripts/show_issue.sh <issue_url>
```
