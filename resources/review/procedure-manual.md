## 手順

各観点によるレビューとその結果の統合は、以下の疑似コードに従って実施してください。

```
レビュー対象観点 = 全レビュー観点から、今回対象外の観点を除いた集合

def レビュー用サブエージェントを起動(観点名):
    # - context fork無しのサブエージェントを起動する
    # - サブエージェントには、`あなたは個別の観点を担当するサブエージェントである`ということを認識させる
    # - サブエージェントには、担当する観点ファイルへのファイルパス・レビューの開始時に保存した各種ファイル・その他レビューに必要な情報を与える
    # - `related_issues.json`もしくは`issue_info.txt`が存在する場合、関連 issue の本文と全コメントを含む一次情報として扱い、要件の背景や議論経緯の確認に利用させる
    # - related_issues.json または issue_info.txt に記載された要件に反する修正提案を行わせない
    # - サブエージェントには、レビュー対象の diff だけでなく、関連するコードを含めて調査し、レビューに役立てるよう指示する
    # - サブエージェントには、指摘が一つ見つかってもそこでレビューを止めず、レビュー対象コード全体を確認して、指摘事項を網羅的に報告するよう指示する
    # - サブエージェントには各指摘ごとに、以下の内容を報告させる
    #    - 指摘の対象ソースファイルと行数
    #    - 指摘の対象ソースコードの該当部分の抜粋
    #    - 担当観点に照らして、何が問題または改善対象なのか
    #    - 指摘の根拠
    #    - 修正案
    # - その他、最終的なレビュー結果を作成するために必要な情報が報告されるよう、適切な指示をサブエージェントに与える
    #     - ただし、サブエージェントには`[P1]`〜`[P8]`の重要度タグをつける指示は与えない
    # - サブエージェントには、レビュー結果をファイルを含めた、ファイルシステム上のファイルの作成・編集・削除を禁止する
    上記コメントの内容を満たす形でサブエージェントを起動する

def 出来るだけサブエージェントを起動する():
  while まだサブエージェントを起動していないレビュー対象観点がある:
    観点名 = 未起動のレビュー対象観点から一つ選ぶ
    レビュー用サブエージェントを起動(<観点名>)
    if サブエージェントの上限で起動できなかった場合:
      break

def 観点別レビュー結果の保存先(観点名):
    return f".agent/temp/review/leader/{観点名}_review_result.md"
def レビュー完了済み(観点名):
    return os.path.exists(観点別レビュー結果の保存先(観点名))
def レビュー結果の検証が完了(観点名):
    return 検証済みフラグ(観点名)  # 検証済みフラグは適宜管理する必要があります
def レビュー結果の検証と記録(観点名):
    観点別レビュー結果の保存先(観点名) からレビュー結果を読み込む
    レビュー結果を検証し、正しい指摘のみを正式なレビュー結果に統合し、記録する
        各指摘の重要度を判定し、`[P1]`から`[P8]`までのタグを付与する
    複数の観点で同じ指摘があった場合、それらは統合して1つの指摘としてまとめる
        観点は統合前のいずれかの観点名を使用する
    検証の結果取りのぞかれた指摘を記録する


while not all(レビュー結果の検証が完了(<観点名>) for 観点名 in <レビュー対象観点>):
  # レビュー結果の検証が完了していない観点がある間ループ
  出来るだけサブエージェントを起動する()
  while True:
      サブエージェントによるレビューが完了するのを一定時間待つ
      if サブエージェントが失敗・中断・結果なしで終了したものがある:
          raise "<観点名>のレビューが想定外の結果で終了しました: <サブエージェントの状態>"
      if 待っている間に完了したレビューが一つ以上ある:
          for 保存する観点名 in 待っている間に完了したの観点名:
              `観点別レビュー結果の保存先(<保存する観点名>)` に、<保存する観点名>のレビュー結果を**報告された書式をそのまま**保存する
          出来るだけサブエージェントを起動する()
          break
  while any(レビュー完了済み(<観点名>) and not レビュー結果の検証が完了(<観点名>) for 観点名 in <レビュー対象観点>):
      # レビューが完了済みだが、検証が終わっていない観点がある間ループ
      対象観点名 = レビューが完了済みだが、検証が終わっていない観点から一つ選ぶ
      レビュー結果の検証と記録(<対象観点名>)
      検証済みフラグ(<対象観点名>) = True

`正式なレビュー結果`と`検証の結果取りのぞかれた指摘`を統合し、`## レビュー指摘の書式`に従って最終的なレビュー結果を生成する
```

## レビュー指摘の書式

- 個別の指摘に重要度を表すタグを付与してください。
  - `[P1]`から`[P8]`までのタグです。重要度が高いものほど、数字が小さくなります。
  - コミット前に修正が必要な指摘には概ね`[P6]`以上の重要度を付与してください。
  - また特殊なタグとして`[FYI]`を用意しています。
  - 各タグの目安
    - `[P1]`: 要件に反することが実装されている。 重大なバグにより根本的に動かない。 など
    - `[P2]`: 要件を満たしていない。 足りない機能がある。 バグによって一部の機能が動かない。 など
    - `[P3]`: よくあるケースの入力に対して、正しい出力が得られない。 など
    - `[P4]`: コーナーケースの入力に対して、正しい出力が得られない。 など
    - `[P5]`: 要件を満たしているが、コードの設計上、より良い構造がある。 命名規則、コメント規約に反している。 など
    - `[P6]`: 変数名・関数名・クラス名などにより良い命名がある。 など
    - `[P7]`: 変更したほうが良い細かい指摘。
    - `[P8]`: 変更したほうが良いかもしれない指摘。 修正するべきかどうか判断が難しいもの。
    - `[FYI]`: 参考情報。以下のような場合に付与します。
        - 指摘対象の挙動・制約・不整合について、コードコメント、関連 Issue、PR 本文のいずれかで、意図的に許容すること、または現時点では対応しないことが明示されている場合。
        - 許容対象となる状態が明示されていれば、その状態から直接生じる影響がすべて列挙されていなくても `[FYI]` としてください。
        - レビュー担当者が影響の大きさ、対応コスト、許容判断の妥当性に同意できないという理由だけで、 `[P1]`〜`[P8]`へ変更してはいけません。
        - ただし、次のいずれかを具体的な根拠とともに示せる場合は、`[FYI]`ではなく適切な重要度を付与してください。
            - コメント等に記載された許容条件が、実際のコードでは満たされていない。
            - 実際に発生する挙動が、明示された許容対象の範囲を超えている。
            - 関連 Issue やPR本文の要件が、その挙動を許容していない。
            - コメント等が認識している挙動とは別のバグ、データ欠損、セキュリティリスクが存在する。
        - `[FYI]`ではなく通常の重要度を付与する場合、指摘には以下を明記してください。
            - 明示されている許容内容または許容条件
            - その条件が満たされていない、または許容範囲を超えていることを示す具体的な根拠
- レビュー観点ごとに項を分けてください
    - 対象のレビュー観点の名前を見出しにしてください
    - その観点での指摘が無ければ、`指摘なし`と記載してください
- 指摘には以下を必ず加えてください。
  - 指摘の対象ソースファイルと行数
    - 複数の箇所にまたがる場合は、すべての箇所を記載してください
  - 指摘の対象ソースコードの該当部分の抜粋
    - 複数ヶ所に対して同じ指摘を行う場合は、代表的な箇所のみで構いません
    - 抜粋の範囲が20行を超える場合は、指摘を理解するのに必要な最小限の抜粋のみで構いません
  - 指摘の概要
  - 指摘の詳細な説明
      - 指摘の根拠を含めてください
  - 修正案
- 検証の結果取り除かれた指摘は、レビュー結果の最後に`## 検証の結果取り除かれた指摘`としてまとめてください
    - `## 検証の結果取り除かれた指摘` には以下の内容を含めてください
        - 指摘の対象ソースファイルと行数
        - 指摘の概要
- プレーンテキストとして読んでも、人間の可読性が十分に高くなるよう、適切な改行や箇条書きを用いてください。
